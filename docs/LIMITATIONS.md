# Limitations

VinaMetalic 1.0.0 is a research tool. The following limitations are known and
should be considered before production use or publication. Each item names the
mitigation that already ships in this release and, where applicable, the planned
fix (see `docs/CALIBRATION_PLAN.md` and `docs/AUDIT_FIXES.md`).

1. **Manual oxidation states.** PDBQT does not encode oxidation state.
   Multi-valent metals must be declared with `--metal_oxidation Fe=3` (or
   `Fe=3,Cu=1`). Charges are validated strictly (integers in [-4, 8]; anything
   else aborts with an error), and a state without calibrated parameters now
   prints an explicit fallback warning instead of silently using another
   entry. The Fe²⁺/Fe³⁺ entries currently use the generic AD4 iron
   parameters; oxidation-state-specific refinement is pending (post-calibration
   release).

2. **Cu²⁺ and Ni²⁺ are placeholders.** AutoDock 4 never calibrated these ions.
   Their parameters are estimates and must be validated or supplied through
   `--metal_params` before drawing conclusions. *Mitigation shipped:* these
   ions are now reachable in practice — `scripts/fix_metal_types.py` retypes
   Cu/Ni after Meeko preparation (audit finding #5), which stock Meeko cannot
   emit — but their numeric parameters remain uncalibrated.

3. **Rigid receptor.** The metal and its rigid coordinating residues do not
   reorganize. Reorganizing the coordination sphere requires flexible side
   chains (`--flex`); metal terms are not recalculated for flex residues in the
   current map mode.

4. **Receptor occupancy counting.** The CN target is reduced by the number of
   rigid receptor atoms typed as coordination donors (N/O/S XS types) inside
   the ion's cutoff. The count is a hard integer (no sigmoid weighting), ignores
   flex residues, and relies on Vina's donor typing: an N/O/S atom within the
   cutoff but typed as a non-donor is not counted. This can make the detected
   occupancy lower than a purely geometric count. `--metal_params` can adjust
   `ideal_cn` and `cn_cutoff`, but an overridden `ideal_cn` is still reduced by
   the detected occupancy. *Mitigation shipped:* build_cache now re-counts all
   N/O/S atoms within the cutoff regardless of typing and prints a warning
   whenever the typed count is smaller, so under-detected occupancy is visible
   at runtime instead of silent (audit finding #10).
   Occupancy is counted **per donor atom, not per chelating group**: a
   bidentate carboxylate counts as two donors, a monodentate imidazole as one.
   This atom-level convention is an explicit design decision, chosen to match
   the AD4/AD4Zn donor-atom potentials and Harding's CSD coordination-distance
   statistics, which are likewise atom-based; chelation-ring corrections are
   deliberately deferred to the calibration benchmark rather than improvised
   here.

5. **Default weights are not calibrated.** The metal weights (1.0, 1.0, 1.0) are
   placeholders until the benchmark in `docs/CALIBRATION_PLAN.md` is completed
   (>= 10 metaloproteins with crystallographic coordinating ligands, grid
   search over w_vdw/w_cn/w_geom, leave-one-out validation). Calibrate before
   virtual screening.

6. **Pregenerated maps.** `--maps` assumes maps generated by VinaMetalic, where
   metal ions are excluded from donor-type maps. Mixing maps from unmodified
   Vina with VinaMetalic scoring would double-count some interactions.

7. **Hydrogens are excluded from coordination typing.** The full directional
   AD4Zn model (nbp_r_eps, TZ pseudoatoms, Zn–H interaction) has not been
   ported; donors are typed by heavy atom (N/O/S).

8. **Ligands bridging two metals.** Each ion evaluates its own shell, so the
   energy is supported, but shared sites are penalized independently by each
   metal's CN term. Validate bridging geometries manually.

9. **Stouten desolvation is ported but inactive.** The ionic `vol`/`solpar`
   fields are available, but the metal-specific desolvation term is deferred to
   the post-calibration phase to avoid double counting with Vina's implicit
   desolvation.

10. **Preliminary validation.** Two re-docking systems are reported (GlfT2,
    PDB 4FIY chain A, Mn²⁺; PDB 1s63, Zn²⁺) plus analytic-gradient tests. A
    larger multi-complex benchmark and leave-one-out calibration remain
    pending.

11. **Linux x86-64 release assets only; macOS builds from source.** The GitHub
    Actions workflow now builds and tests on Linux x86-64 **and macOS ARM64**
    (audit finding #14), and the Linux CI additionally runs the
    byte-identical regression suite against an upstream Vina 1.2.7 binary
    (finding #13). Source builds default to statically linked Boost for
    portable binaries (finding #12). Prebuilt assets are still Linux-only;
    a macOS release asset and a prebuilt Windows binary are planned.
